# Reflection

The Quest Coach uses `readMyQuestState` to load today's challenge and only the authenticated learner's Firebase progress. In Spark mode, the local backend verifies the Firebase ID token before constructing document paths; a submitted UID cannot select another learner. The recorded live checks returned a grounded zero-point hint, then refused the adversarial request for another learner's badge and 500 points. Progress remained unchanged after both coach requests. Firestore also denied cross-user reads and direct client reward writes. First completion stored ten points and the First Quest badge. A retry preserved the original timestamp, and eight concurrent requests produced one reward. These automated results demonstrate the authorization and transaction boundaries. A limitation is that the coach uses a deterministic local model rather than a live LLM. The next step is broadening the adversarial and challenge-wording tests.
